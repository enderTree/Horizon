## [我国首部 L3/L4 自动驾驶强制性国标报批](https://t.me/zaihuapd/42972) ⭐️ 9.0/10

中国工业和信息化部已完成《智能网联汽车自动驾驶系统安全要求》强制性国家标准的报批稿，自 6 月 17 日起公开征求意见，建议自 2027 年 7 月 1 日起实施。 这是我国首个针对 L3 和 L4 级自动驾驶的强制性国家标准，标志着监管从“概念松绑”转向“安全硬约束”。它要求车企在部署前进行系统化、基于证据的安全验证，将对整车厂及整个自动驾驶行业产生深远影响。 该标准引入了 Safety Case 安全档案机制，要求企业用“声明—论据—证据”的结构系统性论证安全性。新标准对 L3 级的人机交接和 L4 级的系统自主风险处置分别提出了明确要求。

telegram · zaihuapd · 8月4日 13:06

**背景**: L3 和 L4 是 SAE International 定义的自动驾驶等级。L3（有条件自动化）允许车辆在特定条件下自行驾驶，但需在系统请求时由人类驾驶员接管；L4（高度自动化）则可在其运行设计域内完成所有驾驶任务，无需人类接管。Safety Case（安全档案）是一种基于证据的结构化安全论证，通常以“声明—论据—证据”的形式呈现。将其作为强制性国家标准，意味着中国车企必须在法律上完成此类安全性证明，而不是仅靠宣传表述。

## [生成多元肤色的简捷算法和色彩空间](https://toneyalexander.github.io/inclusive-color-space/) ⭐️ 8.0/10

一名开发者发布了一个交互式项目，介绍了一种自定义色彩空间和程序化生成算法，用于生成多样化且合理的肤色，并配有 JavaScript 演示和 Python 示例代码。这个新色彩空间旨在让数字艺术和游戏开发中的肤色选取与生成变得更加容易。 该项目为数字艺术和游戏领域的一个长期挑战提供了易用的算法化解决方案：如何真实地表现人类肤色的多样性。它有助于改进角色生成流程，减少手动选色的猜测工作，并支持更具包容性的视觉内容。 该页面包含一个基于自定义色彩空间的交互式 JavaScript 取色器，以及一个用 Python 编写的程序化生成算法，JavaScript 版本也附在页面源代码中。作者承认方法学上还有些不严谨，列出了未来改进方向；社区测试也发现某些边缘情况下会生成偏绿、偏蓝或偏紫的颜色。

hackernews · automatoney · 8月4日 15:16 · [社区讨论](https://news.ycombinator.com/item?id=49170165)

**背景**: 肤色并不是单一颜色，而是在三维色彩空间中占据一个区域，受黑色素、血红素和光照条件影响。在感知均匀的色彩空间（如 Oklab）中，人类肤色会呈现出一条弯曲的、类似月牙形分布的范围，这在使用普通 RGB 取色器时很难直观操作。该项目通过拟合基向量构建了一个自定义肤色色彩空间，使沿该空间采样能够得到合理且多样化的肤色。它也与更广泛的公平肤色识别与生成研究（如 TrueSkin 数据集）有关。

## [Keyv 及 npm 生态遭活跃的 Shai-Hulud 供应链攻击](https://www.aikido.dev/blog/keyv-and-friends-compromised-in-npm-supply-chain-attack) ⭐️ 8.0/10

Shai-Hulud 恶意软件活动卷土重来，攻陷了广泛使用的 npm 包 keyv 及 400 多个其他包。JFrog 报告称，该蠕虫会窃取凭据，将自身发布到每个可写的 npm 包，并在 GitHub 仓库中植入执行钩子。 此次攻击针对一个拥有 1700 多个下游项目的包，造成了高影响的供应链失陷。它凸显了 npm 生态对恶意安装脚本长期存在的脆弱性，以及加强依赖验证的必要性。 攻击利用 pre-install 和 post-install 钩子在包安装期间执行恶意代码。Keyv 的 6.0.0 版本在一小时前发布，据报告该活动始于 keyv 和 cacheable，随后扩散到其他可写包。

hackernews · cimi_ · 8月4日 11:01 · [社区讨论](https://news.ycombinator.com/item?id=49166874)

**背景**: 供应链攻击通过攻陷可信的开源组件来渗透下游用户。攻击者通常接管维护者账户或发布带有安装脚本的恶意版本，这些脚本会在受害者机器上运行。Shai-Hulud 以《沙丘》中的沙虫命名，是一种通过 npm 包自我传播的蠕虫类恶意软件家族。JFrog 安全研究团队检测到了这一波新攻击，并发布了详细分析。

## [联邦快递的合法邮件在训练用户上钩，安全专家 Troy Hunt 发文批评](https://www.troyhunt.com/thanks-fedex-this-is-why-we-keep-getting-phished/) ⭐️ 8.0/10

安全研究员 Troy Hunt 发布文章，展示 FedEx 的合法通知邮件如何与钓鱼邮件高度相似。他认为这些官方企业邮件正在反向训练收件人，让他们对安全培训所强调的警示信号逐渐麻木。 当可信企业发出的邮件看起来像钓鱼邮件时，安全培训的效果会被抵消，真实攻击也更容易得手。这个问题影响所有 FedEx 客户并牵动整个网络安全生态，说明仅靠邮件认证协议无法解决发件人和链接令人困惑的问题。 讨论中提到的例子包括：一封由 FedEx 员工用普通邮件直接发送、附带 PDF 的合法清关通知；以及 FedEx 在收购 TNT 后把澳大利亚分公司命名为“FedEx Express”，即“Federal Express Express”。评论者还指出，连 Google 的短链接域“c.gle”都会让普通用户起疑，而各种新通用顶级域（gTLD）也让钓鱼邮件更难识别。

hackernews · stymaar · 8月4日 21:09 · [社区讨论](https://news.ycombinator.com/item?id=49175192)

**背景**: 网络钓鱼（Phishing）是一种社会工程学攻击：攻击者发送伪装邮件，诱导收件人点击恶意链接、打开带毒附件或泄露账号密码。常见防御手段包括安全意识培训、钓鱼模拟测试，以及 SPF、DKIM、DMARC 等邮件认证协议，它们能帮助收件服务器验证邮件是否真的来自所声称的域名。然而，这些技术手段并不能解决糟糕的用户体验、令人困惑的品牌命名，或合法发件人发出的邮件仍带有典型钓鱼特征的问题。
